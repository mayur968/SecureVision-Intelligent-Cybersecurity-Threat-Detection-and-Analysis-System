This change adds a public landing page at `/`, moves the dashboard to `/dashboard`, introduces a skeleton `AuthContext`, a Stage 2 placeholder `/login` page, and wires up the `/auth` Vite proxy. All seven required landing page sections are present. The quick-scan strip calls the real `api.scanUrl` endpoint via `useMutation`. No fake statistics appear anywhere in the diff. `tsc --noEmit` exits 0.

**Watch for:** `useNavigate` is imported and assigned to `navigate` in `Landing.tsx` but the variable is never called — a dead assignment that tsc does not flag as an error. The `/login` route is registered as a relative path (`"login"`) without a leading slash, which works in React Router v6 but diverges from the `/` and `*` patterns used at the same level.

### Dead `navigate` assignment in Landing.tsx

`useNavigate` is imported alongside `Link` at line 2 and `const navigate = useNavigate()` is declared inside the component body. All CTAs use `<Link>` components, so `navigate` was never called. TypeScript doesn't flag it unused because `useNavigate()` is a hook call and the returned value has a type. The dead assignment is harmless now but will create confusion when Stage 2 engineers see the import and assume it is wired to something.

### `/login` route path inconsistency

In `main.tsx`, the two routes outside `Layout` are written as:

```tsx
<Route path="/"     element={<Landing />} />
<Route path="login" element={<Login />} />
```

React Router v6 resolves `"login"` to `/login` at the top-level `Routes`, so the route works and all `<Link to="/login">` references are correct. The inconsistency is readability: every absolute route on that same level uses a leading slash (`"/"`, `"*"`), and layout-child routes intentionally omit it. `"login"` sits ambiguously between the two conventions. One character fix, no behavioral change.
