## Key observations from codebase read

- `MessageDetector.predict()` returns `{'prediction', 'confidence', 'indicators', 'features', 'model_available', ...}` — risk_score is NOT in its output directly; use `confidence * 100` as fallback base score when model is unavailable.
- `URLDetector.predict()` returns `{'prediction', 'confidence', ...}` — wrapping each call in try/except is required as the plan specifies.
- `ScanHistory` already has `risk_score`, `user_id`, `anon_session_id`, `scan_type`, `prediction`, `confidence`, `risk_level` columns — no schema migration needed.
- `app.py` calls `ScanHistory.get_statistics()` and returns `stats` directly inside `jsonify({'success': True, 'statistics': stats})`. The `email_scans` field must be injected into `stats` dict after calling `get_statistics()`, not added to `get_statistics()` itself (to avoid modifying models.py).
- `Sidebar.tsx` uses a `NAV_ITEMS` array of `{ to, icon, label }` — the Email icon must be an inline component matching the pattern.
- `client.ts` imports only named types from `../types/index.js` — `EmailScanResult` must be added to that import line.
- `RiskBadge` accepts `level?: RiskLevel` or `prediction?: Prediction` — for `risk_level` string values ('LOW'|'MEDIUM'|'HIGH') pass as `level=`.
- `ScanTypeExtended` in `types/index.ts` will need `'EMAIL'` added to its union so `HistoryScan` displays correctly in History page.
- The router in `main.tsx` wraps each scanner in `<ErrorBoundary>` — `EmailScanner` must follow the same pattern.
- Playwright node script must use `require('playwright')` from `c:\Users\Mayur\Documents\SecureVision\node_modules` (not `client/node_modules`).

## Notes and assumptions

- **`SUSPICIOUS` prediction value**: `RiskBadge` currently handles `SAFE`, `PHISHING`,
  `MALICIOUS`, `UNKNOWN`, `ERROR` in `predStyles`. `SUSPICIOUS` is not in the map and will
  fall through to `predStyles['UNKNOWN']` styling. This is acceptable for now; if Stage 4
  adds a dedicated style, add `'SUSPICIOUS'` to `predStyles`. No change needed in Stage 3.

- **`ScanHistory.get_statistics()` patching**: The statistics route calls
  `stats = ScanHistory.get_statistics()` which returns a plain dict. The plan injects
  `email_scans` into that dict after the call — this avoids modifying `models.py` and keeps
  the change minimal and reversible.

- **Model availability in tests**: Tests 1–9 call `scan_eml()` without passing detectors.
  The scanner will lazy-import `MessageDetector` and `URLDetector`, which may or may not have
  their model files. All detector calls are wrapped in `try/except` so tests must pass
  regardless of model presence — the risk score will use defaults but the structure is intact.

- **`io` import in test 10**: `io.BytesIO` is needed for the multipart upload; the test file
  must import `import io` at the top.

- **Brand words for `display_name_mismatch`**: Use a small hardcoded set of common brand
  keywords: `{'paypal', 'amazon', 'apple', 'google', 'microsoft', 'netflix', 'bank',
  'chase', 'wellsfargo', 'citibank', 'ebay', 'fedex', 'ups', 'dhl', 'irs', 'usps'}`.
  Mismatch fires when any brand word appears in the From display name but the From domain
  does NOT contain that brand word.
